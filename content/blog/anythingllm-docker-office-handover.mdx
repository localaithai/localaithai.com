สำหรับคนรับมอบ AI ในออฟฟิศ คำถามสำคัญคือระบบประมวลผลที่ไหน ใช้ทรัพยากรอะไร และเปิดงานเดิมหลังเริ่มเครื่องใหม่ได้หรือไม่ การติดตั้งที่รวมส่วนประกอบมากขึ้นควรทำให้หลักฐานเหล่านี้อ่านง่ายขึ้นด้วย

## AnythingLLM 1.19 เปลี่ยนส่วนใด

[AnythingLLM 1.19.0 วันที่ 26 ตุลาคม 2026](https://github.com/Mintplex-Labs/anything-llm/releases/tag/v1.19.0) เพิ่มเอนจิน local ใน Docker แบบเลือกเปิด ใช้ Lemonade ของ AMD กับ llama.cpp โดยไม่ต้องมีบริการ Ollama หรือ LM Studio ข้าง container สำหรับ provider นี้

[รายละเอียดการพัฒนา](https://github.com/Mintplex-Labs/anything-llm/pull/6719) ระบุว่าปิดตัวเลือกนี้ไว้เริ่มต้น ต้องเปิดจากค่าตอนเริ่ม container และยังต้องส่ง GPU ให้ container ใช้ เอนจินถูกดาวน์โหลดตอนทำงาน ส่วน backend มีทั้ง CUDA, Vulkan และ CPU ตามชุดที่ใช้จริง

## เอกสารส่งมอบควรแสดงอะไร

ตารางนี้เป็นแบบคุยกับผู้ติดตั้งที่เสนอให้เจ้าของกิจการใช้ ไม่ใช่ผลวัดความเร็วหรือการตรวจระบบของเรา ให้เริ่มจากข้อมูลสมมติที่คนตรวจรู้คำตอบ แล้วขอดูหลักฐานชุดเดียวกับการตั้งค่าที่จะส่งมอบ

| รายการรับมอบ | สิ่งที่ข่าวเพิ่มให้เลือก | หลักฐานที่ควรขอดู | คนรับผิดชอบที่ต้องระบุ |
| --- | --- | --- | --- |
| จุดประมวลผล | provider ใน Docker | provider และปลายทางของงานตัวอย่าง | ผู้ตั้งค่าระบบ |
| การใช้ทรัพยากร | เอนจินเลือก backend ได้ | backend จากบันทึกและทรัพยากรขณะทำงาน | ผู้ติดตั้งฮาร์ดแวร์ |
| การเตรียมไฟล์ | ดาวน์โหลดเอนจินตอนทำงาน | รุ่นไฟล์ แหล่งดาวน์โหลด และช่วงที่อนุญาต | ผู้ดูแลการอัปเดต |
| เริ่มระบบใหม่ | รวมเอนจินในเส้นทางติดตั้งนี้ | เปิดงานตัวอย่างเดิมและพบข้อมูลถูกชุด | ผู้ดูแลประจำ |
| การเชื่อมภายนอก | ยังต้องเลือกส่วนอื่นของงาน | แผนข้อมูลและรายการปลายทางที่ตกลง | เจ้าของข้อมูลกับผู้ดูแล |

อย่าตัดสินการใช้ GPU จากการเห็นชื่อ GPU บนหน้าจอเพียงอย่างเดียว ให้ผู้ติดตั้งผูกหลักฐานกับคำขอตัวอย่างและการตั้งค่าที่ใช้ หากเปลี่ยนไปใช้ CPU โดยไม่รู้ตัว ผลการประเมินเวลาของงานจะไม่ตรงกับเครื่องที่ตกลงซื้อ

## แยกช่วงดาวน์โหลดกับช่วงใช้ข้อมูลบริษัท

ก่อนนำเอกสารจริงเข้า ให้กำหนดว่าขั้นเตรียมเอนจินและโมเดลต้องเชื่อมต่ออะไร หลังเตรียมเสร็จจึงทดลองขอบเขตเครือข่ายของงานที่ตกลงไว้ พร้อมวิธีแจ้งปัญหาเมื่อบริการที่จำเป็นใช้ไม่ได้

ตรวจระบบค้นเอกสารและ embedding แยกจาก provider ที่สร้างคำตอบ รวมถึงเครื่องมือที่เปิดใช้และที่เก็บไฟล์ส่งออก การรวมเอนจินนี้ลดส่วนที่ต้องติดตั้งแยกในเส้นทางดังกล่าว แต่ไม่ได้ตอบแทนว่าทุกส่วนของงานอยู่ในบริษัทแล้ว

## ปิดการรับมอบด้วยงานที่ทำซ้ำได้

ขอให้คนที่จะใช้จริงลองงานเดิมหลังเริ่มระบบใหม่ และเก็บว่าอะไรยังต้องให้ผู้ติดตั้งช่วย ใช้ผลนั้นวางขั้นตอนตาม[การทำงานของ AI ภายในออฟฟิศ](/how-it-works/) โดยตกลงทั้งการใช้งาน การแก้เหตุ และการเปลี่ยนรุ่น ข่าวนี้ไม่ได้ยืนยันคุณภาพงานไทยหรือการรองรับเอนจินนี้ใน Mimir

[วิดีโอ AnythingLLM จาก Tim Carambat](https://www.youtube.com/watch?v=Z6kK4DXqCOI) เป็นตัวอย่างเก่าของแอปและงาน agent ในเครื่อง ไม่ใช่เดโมเอนจิน Docker รุ่น 1.19
